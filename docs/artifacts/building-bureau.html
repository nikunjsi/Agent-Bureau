BuildingBureau

An office where the staff are AI — and the sixteen stages that put it up, one floor at a time.

Bureau is a Windows app. You describe a project in chat. A manager agent called the Director interviews you, writes a plan, and hands the work to AI employees — each one a real coding tool running on your machine, each with its own copy of your project. You watch it happen on a pixel-art office floor.

It is being built in a deliberate order, and the order is the interesting part. The rewarding-looking work — the office you can actually see — comes almost last, because it holds nothing up. This page walks the whole structure from the foundations, in plain language, with a glossary at the end for every technical word used.

Before anything else

Who is in the building

Four kinds of thing live in Bureau. Almost everything in this document is about making one of them safe, honest, or possible.

You The only human

You talk in a chat box. You approve plans, answer questions, set budgets. You never have to open a terminal or read a diff.

The Director Manager agent

Interviews you, writes the brief, plans the work, assigns it, reviews it, reports back. It never edits a file itself — so "who changed this?" always has one answer.

Employees Worker agents

Real AI coding tools, run as separate programs on your machine. Each gets a private copy of your project. They write files. They never run git.

The Core Bureau itself

The plain, non-AI code holding it together. It starts and watches the agents, checks every action, counts the money, and is the only thing allowed to save work permanently.

The thing it all exists for

What using it actually looks like

One project, start to finish. Nothing gets built before you approve the brief — a rule the system enforces on itself, not a promise it makes.

The route

Sixteen stages, bottom to top

Each stage has a gate — a specific thing demonstrated with real output before the next one starts. Not "we think it works." Shown. The four colour bands below are the project's own review boundaries: work stops at each one for an independent audit.

Band 01

Make it stand up

Nothing here is visible to a user. All three stages exist to defuse failures that are cheap to fix now and ruinous to fix later.

M0

Skeleton

Finished1 session

An empty window that opens — but opened the way a real user would get it: installed, not run from the workshop.

  • The window, locked down so the visible part of the app has no power of its own
  • Two components that must be recompiled for this exact app, proven to load inside the installed version
  • A containment box, so killing Bureau kills every AI process it started
How we knew it was doneThe packaged app opened, both tricky components loaded inside it, and killing the app left nothing running behind.
Why first: an app usually works fine in the workshop and breaks the day you package it. Finding that on day one costs an afternoon. Finding it in month three costs a rewrite.
M1

The memory

Finished2 sessions

Everything Bureau remembers — projects, tasks, employees, money spent, every event — and it must survive being killed at any instant.

  • A local database file; no server, nothing leaves your machine
  • Every change written down before the thing it describes happens — so a crash leaves a note about something unfinished, never a finished thing with no note
  • A repair pass at startup that reconciles whatever a crash left behind
How we knew it was doneThe app was killed at twenty scripted moments. Every one recovered cleanly, three runs in a row, nothing lost.
M2

The window and the bridge

Finished2 sessions

Bureau is really two programs: one that draws pixels, one with real power. This stage builds the guarded doorway between them.

  • Every request across the doorway checked against a strict shape before anything acts on it
  • The drawing half given no access to your files or the internet — if compromised, it could do nothing
  • The actual layout: office view, chat panel, employee bar, light and dark themes
How we knew it was doneTwo security tests: the visible half genuinely has no file access, and a deliberately malformed message is dropped rather than quietly patched up.
A lesson that stuck: a real bug shipped here that no automated check caught. It only appeared when someone launched the actual installed app and looked. Every stage since has included "run the real thing and look at it."
Band 02

Bring in the staff — safely

An AI process actually runs, can report back, gets its own workspace, and is contained so it can neither wreck your machine nor empty your wallet.

M3

Running a real agent

Finished3 sessions

Bureau starts a real AI coding tool as a separate program, watches it, and translates everything it says into one common language.

  • An adapter per tool, so Bureau isn't welded to any one AI product
  • A supervisor owning each agent's process — starting, watching its pulse, counting turns, stopping it cleanly
  • A fake agent built first, so everything downstream can be tested without spending money
How we knew it was doneA real agent completed a real task with its output visible, and stopping it left no stray processes.
Caught late, and worth it: a final end-to-end check found the supervisor was starting employees without ever telling them what their task was. Every piece passed its own test; the seam between them was broken.
M4

Letting agents talk back

Finished2 sessions

Until this stage, Bureau could speak to an agent but never hear from it. Nothing above this line works without it.

  • A private line only programs on your own machine can reach
  • Eight things an employee can say: I've started · I'm stuck · I have a question · I'm finished · and so on
  • A gatekeeper every tool an agent tries to use must pass through first
How we knew it was doneA real agent set its status, asked the Director a question, and finished a task — all three landing in the database. Unscripted, it also tried a tool it wasn't allowed, and was correctly refused.
Fail closed: if Bureau itself dies while an agent waits for permission, the answer is no. Proven by killing the real process mid-question, not by simulating it.
M5

Everyone gets their own desk

Finished2 sessions

Every employee gets a private copy of your project, and their finished work is combined back together without them ever touching your real files.

  • A private working copy per employee, created when hired, removed when fired
  • Work saved by the Core only — after inspecting the changes and running checks, including a secret scanner that cannot be switched off
  • Merging happens only after work is accepted, never merely finished
  • Clashing changes are never guessed at — the task stops and you are asked
How we knew it was doneThree employees committed and merged in parallel, cleanly. A deliberate clash produced a proper question rather than a mangled project. A 102-cycle endurance run passed clean.
An honest downgrade: the strongest possible lock — making it physically impossible for an employee to save work — was attempted for real and failed for a genuine Windows reason. Rather than quietly claiming it anyway, the headline promise was rewritten downward to what is actually true: employees are prevented by policy, and any unexpected save is detected and flagged.
M6

Containment and money

Under construction3 sessions · 2 done

The stage that answers the real question: can I leave this running on my machine?

  • A rulebook deciding every single action an agent attempts — allow, ask, or refuse
  • Rules nothing can override: never write outside your own copy, never read credentials, never touch system folders, never spawn hidden helpers
  • Three trust levels per employee — ask me everything, guided, autonomous — where "nothing outside the workspace" holds at all three
  • Spending caps at four levels, a live meter, and rate-limit handling that waits politely instead of looking like a crash
  • A loop detector and a circuit breaker for an agent going in circles
What will prove itEleven security tests green. A refused command provably never runs. An employee over budget parks itself. A rate limit backs off and resumes on its own.
Where it is right now: the rulebook and trust levels are built and tested. The money half — pricing, budgets, rate limits — is in progress. The circuit breaker and the secret-redactor are the final session.
Band 03

Make it a product

Everything so far is plumbing only a test can appreciate. This band is where Bureau becomes something you can sit down and use.

M7

Job descriptions become files

To come2 sessions

What a "developer" or a "reviewer" is stops being code and becomes an editable text file — so a new kind of employee needs no programming.

  • Packs: installable bundles of roles, each stating exactly what it grants
  • The first real team — five engineering roles with real instructions
  • Hiring: names, desks, sprite variants, a memory of their own
  • The office floor plan generated as plain data — no graphics yet, just the map
What will prove itHire three employees across two departments; the floor plan stays identical across restarts; a deliberately broken pack is rejected with a message a human can read.
M8

Asking you things properly

To come2 sessions

The back-and-forth mechanism. Every question an agent raises, how urgent it is, what happens if you don't answer, and how it reaches you.

  • Every option must state its consequence — a question that doesn't is rejected before you ever see it
  • Related questions arrive together instead of one at a time; urgent ones never wait
  • An unanswered question resolves to the safe option, never "proceed"
  • A grace period after a restart, so reopening the app never auto-answers a backlog
What will prove itA permission request holds an agent mid-task, gets answered on screen, and the agent carries on. An unanswered urgent one resolves safely. A question to a dead employee produces a visible problem, not silence.
M9

The chat

To come2 sessions

The main interface — good enough to live in, because for most users it is Bureau.

  • Every kind of message rendered properly: plans, briefs, reports, questions, errors
  • Live streaming as the Director types, and a clearly marked cut-off if the app dies mid-sentence
  • Approve / Edit / Discuss on briefs and plans, with editing opening the real document
  • Typed shortcuts like /pause and /budget handled outside the AI, so they work even when the Director can't respond
What will prove itA full conversation, including approving a brief, works end to end. Killing the app mid-sentence leaves a clearly marked incomplete message rather than a lie.
M10

It stops repeating itself

To come1 session

Memory. A decision you made on Monday is still known on Friday, without you saying it twice.

  • Relevant past decisions pulled into the Director's context, within a strict size budget
  • Nothing written to memory without passing a gate — agents propose, they don't decide
  • Memory files you can open, read, edit, and pin yourself
What will prove itA decision recorded in one session is demonstrably present in the next one's context — verified by inspecting the record of what was loaded, not by asking the AI whether it remembers.
M11

The Director

To come3 sessions

The most important stage in the whole build. This is where the product starts existing rather than being scaffolding.

  • A single long-lived manager session that survives restarts and remembers the project
  • Interviewing you in batches, capping the rounds, handling "you decide" gracefully
  • Writing the brief, then the plan — phases, tasks, and what depends on what
  • Handing out work automatically, using plain code rather than an AI turn per assignment
  • Judging finished work against its acceptance criteria: accept, follow up, or escalate to you
What will prove itDescribe a real project in chat, be interviewed, approve the brief and plan, watch employees work, review a phase, and end up with something real. Then actually use it on something real before moving on.
The plan says so explicitly: a week of genuine use here will find things no amount of specification predicts. Everything before this can only be judged by tests.
Band 04

Make it real for other people

The visible office, the install experience, and everything separating "works on the builder's machine" from "a stranger can use this."

M12

The office you can see

To come3 sessions

The pixel-art floor: little people at desks, walking, thinking, stuck, waiting on you. Readable in one second.

  • One pure function turning real system state into a visual state — the only path there is
  • Sprites, speech bubbles, walking, desk-dragging, click and hover
  • Respecting reduced-motion settings; smooth at 60fps with twenty employees
What will prove itEvery employee state is visually distinct and provably matches something real. And Bureau stays entirely usable with the office collapsed — it's a view, never a requirement.
Why this is nearly last: it's the most rewarding-looking work in the project and the least load-bearing. Building it early is how a plan quietly becomes twice as long.
M13

Getting started with nothing

To come2 sessions

A person with a fresh Windows machine and no tools reaches a working first project without ever opening a terminal.

  • Detect what's missing, show the exact command, ask consent, install, then re-check
  • Free options presented first, with honest wording about where free runs out
  • A mandatory budget step — you set a limit before anything can spend
  • Resumable at every step; every failure comes with copy-paste manual instructions
What will prove itOn a clean machine with nothing installed, complete the setup and reach a working conversation — no terminal, start to finish.
M14

The rest of the app — and a real test of the design

To come2 sessions

The task board, the per-employee inspector, and a second team type written without touching a line of engine code.

  • Board view: phases, tasks, what's blocked on what, full history per task
  • Inspector: activity in plain language, the raw terminal if you want it, files and changes
  • A research-and-writing pack and an operations pack, authored as data only
What will prove itA research-only project — no code at all — runs end to end. And adding the second pack required zero engine changes. If code had to change, the abstraction was wrong, and this is the moment that finds out.
M15

Shippable

To come3 sessions

A signed installer, automatic updates, and the full battery of endurance and abuse testing.

  • An installer needing no administrator rights, properly signed so Windows trusts it
  • The complete security suite, a hundred-task endurance run, and the deliberate-chaos list
  • A claim audit: every promise the app or its README makes must map to a passing test — or the promise gets removed
What will prove itThe whole suite green, performance budgets enforced automatically, and no claim anywhere in the product that isn't backed by something that passes.
Plain meanings

Every technical word, unpacked

In the order you'd meet them, not alphabetically.

Agent
An AI given a job, tools, and the ability to act on its own for a while — rather than just answering one question.
The Core
Bureau's own ordinary, non-AI code. It supervises, checks, counts and saves. Most of the safety here comes from doing things in plain code instead of asking an AI nicely.
Packaged app
The installed version a real user gets, as opposed to the version a developer runs. They load files differently, which is why the difference matters so much.
Native module
A component that must be recompiled to match the exact app it runs inside. Get it wrong and it fails only after installation — never during development.
Orphan process
An AI program still running after the app that started it has died. Bureau puts every child in a container that dies with it.
Reconcile
The repair pass at startup. It compares what the records say against what is actually true on disk, and fixes the difference.
Adapter
A translator for one specific AI tool, turning its particular output into the single format Bureau understands. New tool, new adapter, no changes elsewhere.
Supervisor
The one thing allowed to manage a given employee's process — start, watch, count turns, stop. Exactly one per employee.
Turn
One round of an agent thinking and acting. A single task can take fifteen to forty, which is why free plans run out sooner than their advertised numbers suggest.
Control channel
The private line agents use to talk back to Bureau. It only accepts connections from your own machine, and each employee gets its own key.
Hook
A checkpoint the AI tool itself calls before running any tool, letting Bureau approve or refuse first. If Bureau can't be reached, the answer is no.
Fail closed
When something is unclear, broken, or unreachable, choose the safe option. Never the convenient one.
Git
The standard system for tracking changes to files over time — who changed what, when, and the ability to go back.
Worktree
A second, separate folder holding its own copy of the project while sharing one history. This is how three employees edit the same project at once without colliding.
Branch
A named line of work that can be developed separately and combined later.
Commit
A saved snapshot with a message explaining it. In Bureau only the Core makes these — employees write files, never snapshots.
Merge
Combining two lines of work. If they changed the same thing, that's a conflict — and Bureau never guesses the resolution.
Lease
A time-limited claim on a workspace, so two employees can never be handed the same one. It expires, so a crash can't lock it forever.
Validator
An automatic check run before work is saved — style, tests, and a secret scanner that cannot be turned off.
Autonomy level
How much rope an employee gets: ask me everything, guided, or autonomous. "Nothing outside the workspace" applies at all three and can't be changed.
Immutable deny
A refusal nothing can override — no setting, no add-on, no job description. Reading your credentials is one of these.
Checkpoint
A question Bureau asks you. Every option must state its consequence, and an unanswered one resolves to the safe choice.
Circuit breaker
The safety switch for an agent going in circles: interrupt, redirect, tighten its permissions, and only then stop it — because killing it mid-write loses work.
Micro-dollars
Money stored as whole millionths of a dollar rather than decimals, so repeated addition never drifts by a fraction of a cent.
Pack
An installable bundle of job descriptions and standards. The test of the design is whether a whole new department can be added without changing any code.
Gate
The specific thing demonstrated with real output before a stage counts as finished. Not an opinion — a demonstration.
Mutation test
Deliberately breaking the code to check the test actually fails. A test never seen to fail isn't evidence of anything.
Soak test
Running the same operation a hundred-plus times to find the rare failure that only appears under sustained load.
Prompt injection
Hidden instructions planted in a file or web page, hoping the AI reading it will obey. Bureau contains this rather than claiming to prevent it: a hijacked agent still cannot exceed the permissions it was given.
The rule behind the rules

Nothing is claimed more strongly than the mechanism supports

The most unusual thing about this project isn't technical. It's that when something can't be built as promised, the promise gets rewritten downward in the same change — not left standing while a footnote elsewhere quietly disagrees.

That has already happened once, at the workspace stage. The strongest possible protection against an employee saving work directly was attempted properly, failed for a real Windows reason, and the headline rule was rewritten to say what is actually true. It also happened to a cost display that could have shown a misleading zero, and to a merge rule that two parts of the specification described differently.

The final stage carries this to its conclusion: a claim audit, where every promise the app makes must point at a test that passes — and any promise that can't is deleted rather than defended.
