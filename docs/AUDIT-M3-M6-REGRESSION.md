## What M11 inherits that this check could not prove

1. **Audit #13: §10.6 rules 5 and 6 are still entirely absent, and the deferral's reason expires now.** No phase-acceptance merge into `base_ref`, no push path, no `git.pushed` (Part 1 #13). M11 builds phase acceptance, rule 5's trigger, so rule 5 must land in the same session or §10.6's branch topology is decorative. Rule 6 (push is an approval checkpoint) must not be built on `deny.git_write`'s pattern, which a bare `git push` already evades (N-9).
2. **The Director can be stopped**, by `breaker.hardStop` or `budgets.onExceed: stop`, despite a guard whose comment says it cannot be (N-16, probed). The wall-clock breaker will trip a long-lived Director an hour after it starts.
3. **A paused Director's in-flight turn is never recorded** (N-1, probed). claude-code cannot be interrupted, and the parked gate drops the turn's usage. The reserve, the budgets and the ledger under-count.
4. **Secrets redacted on the live push reappear through request/response IPC**, including `chat.listMessages` on every window load, which is the Director's own chat (N-2, probed).
5. **No production code has ever created a Supervisor.** `spawnSupervisedEmployee` has no caller, so registration, live capabilities for policy (N-3) and the shutdown sequence's handling of a live engine are all untested in production shape. Shutdown stops no Supervisor (Part 4 §1).
6. **The hook binary every Director tool call passes through has fail-closed branches no free test runs** (N-14, probed).
7. **Unproven:** the Director side of the *project*-level reserve (N-5); a Supervisor that lives for hours across many user turns; that a UI probe will pass a budget (Part 4 §2: make `budgetMs` required); and the worktree lease, which M11's assignment path must either take and renew or formally retire (N-11).

## Part 4 — what M11 stands on

### 1. The supervisor (`src/main/engine/supervisor.ts`)

**What M11 asks of it.** Run the Director as a long-lived supervised session: spawned, registered, paused and resumed by the user, metered, budget-checked with the reserve carve-out, never stopped while it is the user's only way back, and shut down cleanly on quit.

**What today's tests prove.** `assign()` through FakeAdapter, and the four real-adapter/queue proofs. Budget park and stop for non-Directors (S7, `parkedIsAGate`). The Director reserve at `globalDaily`, fired by a Director hired through the production path (`directorReserveLive`). The Director constrained but not stopped by the breaker **with `hardStop` off**. Pause/resume is reachable (M9 s2).

**What they do not prove, and M11 needs:**
- **No production path creates a Supervisor.** `spawnSupervisedEmployee` has no caller (`index.ts:121` says so), so `assign()` in production, `SupervisorRegistry` registration and everything that reads the registry (policy capabilities, N-3) are test-only. M11 writes the first caller.
- **The Director can be stopped** by `breaker.hardStop` or `budgets.onExceed: stop` (N-16, probed), and a long-lived Director trips the wall-clock breaker an hour after `assign()`.
- **A pause during a claude-code turn loses that turn's spend** (N-1, probed). claude-code cannot be interrupted, and the parked gate drops `turn.completed`. §14's pause is explicitly allowed on the Director.
- **Shutdown stops no Supervisor.** `runShutdownSequence` (`shutdownSequence.ts:70-117`) drains the control channel and closes the DB. It has no Supervisor target, because none exists yet. M11 must add one ahead of `db.close()`, or a Director turn completing during quit writes to a closed database.
- **Wall-clock and heartbeat semantics for a session with no task.** `assignedAt` is set per `assign()`. Nothing tests a Supervisor that lives for hours across many user turns.

### 2. The adapter (`claudeCodeAdapter.ts`) after `55b4c22`

**The probe budget.** The default is the 30 s ceiling, decided in **two** places that agree today: `claudeCodeAdapter.ts:261-264` and `probeCache.ts:106`. Current callers are correct. `Supervisor.assign()` passes the ceiling deliberately (`supervisor.ts:546-548`, with its reasoning), and the one caller with a person waiting, `canEnableZeroCostMode`, passes `PROBE_RESPONSIVENESS_BUDGET_MS` (`zeroCostMode.ts:147-149`).

**Is it a real risk once M11 probes?** **Yes, but it degrades to slow, never to wrong.** A UI caller that forgets the budget, such as a "Director ready?" indicator or a setup screen, would hold a spinner for up to 30 s on a cold CLI instead of getting `indeterminate` at 2.5 s. It would never get a false "not installed", which was the bug `55b4c22` fixed. Two sharper edges:
- `ProbeCache` single-flights only when budgets match (`probeCache.ts:111-112`). A UI probe at 2.5 s racing `assign()` at 30 s launches **two** `claude` processes, the cost the M7 cache was built to avoid.
- Nothing mechanical stops the omission.

The cheapest guard is to make `ProbeOptions.budgetMs` **required**, so every call site states which bound it means. This is not recorded as a finding because no caller is wrong today. It is a condition on M11's first UI probe.

**Other adapter facts M11 inherits.** `interrupt: false` in structured mode (`:500`) is load-bearing for N-1 and N-16 and for the breaker's steer (skipped entirely). Each `send()` is a fresh `claude -p` process.
